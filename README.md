# 空调帮 — 空调维修接单小程序

"维修版货拉拉":用户发布空调维修需求 → 同城师傅抢单 → 上门维修 → 维修费当面直付师傅 → 评价。
平台收入 = 师傅会员费(MVP 阶段线下收款、管理后台手动开通);**平台不代收维修费,无资金二清风险**。
另有**买空调频道**:审核通过的师傅上架新机/二手空调,买家浏览 → 平台按次取号电话联系 → 线下当面验货交易,**平台同样不代收货款**。

技术栈:微信原生小程序 + 微信云开发(云函数 Node.js / 云数据库 / 云存储 / 定时器)。
**无需服务器、无需域名备案、无需构建工具**,月成本约 20-30 元。

## 项目亮点

- **原子抢单**:云数据库条件原子更新(`where(status=='published').update(...)`)天然防并发,两人同时抢只有一人成功,无需分布式锁
- **隐私分级**:用户手机号仅在师傅抢单成功后可见,订单池/围观视角一律脱敏;师傅身份证照片仅管理员可见;删号申请 + 180 天历史数据自动脱敏(定时器)
- **合规设计先行**:平台不碰交易资金(会员制而非抽佣,规避二清);全量用户文本过 `msgSecCheck`、图片过 `mediaCheckAsync` 内容安全
- **状态机驱动**:订单 `published → accepted → pending_confirm → completed` 全程条件原子流转,超时关单/自动确认由定时器兜底
- **工程质量**:37 个离线测试文件覆盖业务规则(并发抢单/城市归一化/脱敏/幂等),GitHub Actions CI + 共享代码一致性检查

## 部署步骤(第一次约 1-2 小时)

### 0. 替换占位配置

开源模板已把真实信息替换为占位符,部署前必改:

| 文件 | 占位项 | 说明 |
| --- | --- | --- |
| `project.config.json` | `appid: "touristappid"` | 换成你的小程序 AppID |
| `miniprogram/utils/config.js` | `CLOUD_ENV` | 云开发环境 ID |
| `miniprogram/utils/config.js` | `COMPANY_NAME` | 运营主体营业执照全称(协议页展示) |
| `miniprogram/utils/config.js` | `SERVICE_PHONE` | 真实客服电话(占位号码提审会被拒) |

### 1. 注册小程序(企业主体)
- 到 https://mp.weixin.qq.com 用公司营业执照注册小程序(300 元认证费,需对公打款验证)
- 服务类目建议:**生活服务 > 家政/家电维修**(企业主体资质即可)
- 记下 AppID

### 2. 导入项目
- 下载安装微信开发者工具(稳定版)
- 导入本目录,把 `project.config.json` 里的 `"appid": "touristappid"` 换成你的 AppID

### 3. 开通云开发
- 开发者工具顶部点「云开发」→ 开通(选**按量付费**)
- 记下环境 ID,填到 `miniprogram/utils/config.js` 的 `CLOUD_ENV`
- 同文件**必改两项**:`SERVICE_PHONE`(真实客服电话,占位号码提审会被拒)、`COMPANY_NAME`(公司营业执照全称,协议页展示)
- 云开发控制台 → 存储 → 权限设置:改为**「仅创建者可读写」**。照片展示已全部改经云函数换临时链接,不受影响;这样任何人拿到 fileID 也读不到师傅身份证照片

### 4. 部署云函数
- 在开发者工具里,右键 `cloudfunctions` 下的**每个**函数目录 → 「上传并部署:云端安装依赖」
- `cronTimeout` 上传后,右键它 → 「上传触发器」(启用每小时定时任务)

### 5. 初始化数据库
1. 云开发控制台 → 数据库 → 手动创建集合 `config`
2. 在 `config` 集合中添加文档,**文档 ID 填 `app`**,内容:
   ```json
   { "adminOpenids": ["你的openid"], "tplNewOrder": "", "tplOrderTaken": "", "tplOrderFinish": "", "tplOrderRejected": "" }
   ```
   你的 openid 获取方式:编译运行小程序 → 「我的」页最底部**长按**"复制我的用户标识"
3. 用管理员身份进小程序 → 我的 → 管理后台 → 点底部「初始化数据库集合」,自动创建其余集合
4. **给集合建索引**(云开发控制台 → 数据库 → 集合 → 索引管理,方向按下面标注选"升序/降序"):
   - `orders`:**`status↑ + cityKey↑ + category↑ + publishedAt↓`**(订单池核心查询,必建——查询还带 publishedAt/expectEnd 范围条件和 publishedAt 倒序,这条复合索引与其对齐;城市维度用归一化的 cityKey,不再用 cityName)
   - `orders`:`userOpenid↑ + publishedAt↓`(我发布的)
   - `orders`:`masterOpenid↑ + acceptedAt↓`(我的接单)
   - `orders`:`status↑ + publishedAt↑`、`status↑ + finishedAt↑`(cronTimeout 定时关单/自动确认)
   - `masters`:`openid↑`(唯一)、`status↑`、`status↑ + cityKey↑ + memberExpireAt↑`(发单后圈同城有效会员推订阅通知)、`status↑ + cityKey↑ + memberExpireAt↑ + lastNotifiedAt↑`(新单通知轮转选取;memberExpireAt 是范围条件,排序在内存完成,单城师傅量大后如变慢再调优)
   - `reviews`:`orderId↑`
   - `complaints`:`orderId↑ + status↑`(投诉单单去重查询)、`fromOpenid↑ + createdAt↓`(24h 限频)
   - `listings`(买空调频道):**`status↑ + createdAt↓`**(市场"全部"+管理员筛选)、`status↑ + condition↑ + createdAt↓`(新机/二手筛选)、`sellerOpenid↑ + createdAt↓`(我的上架)、`sellerOpenid↑ + status↑`(在售数上限/批量下架/重挂复核)
   - `contact_logs`:`viewerOpenid↑`(仅删号清理用;日常取号额度按 _id 点查)
5. **建完索引做订单池自检**:管理后台底部点「订单池自检」,它会用与真实订单池完全相同的查询(含第二页翻页)跑一遍——报错说明索引没建对或查询组合不被支持,**不要带着自检失败上线**。有测试数据(建议 25 条以上、跨城市/品类/含过期单)时结果更有说服力
6. **重要**:所有集合的权限保持默认(「仅创建者可读写」)即可——前端所有读写都走云函数,不依赖集合开放权限,这是有意为之(保护手机号等隐私)

### 6. 图片内容安全回调(建议上线前配好)
- 用户照片与师傅资质照片会经 `mediaCheckAsync` 异步送检,结果需要微信回调:
- 云开发控制台 → 设置 → **消息推送** → 添加:消息类型 `event`,事件类型 `wxa_media_check`,推送模式选**云函数**,目标选 `mediaCheckCallback`
- 不配置也不影响功能(照片不会被检测,fail-open),但提审与运营有风险,建议务必配置
- 违规处理策略:订单/商品照片(对外公开)自动摘除并删文件,商品照片被摘光时自动下架;师傅资质照片(仅管理员可见)只标红提示,由审核判断

### 7. 订阅消息(可选,建议上线前配好)
- mp.weixin.qq.com → 功能 → 订阅消息,申请四个一次性模板(前两个上线前必配,后两个强烈建议):
  - **新订单提醒**(推给师傅):字段如 服务类型/所在区域/期望时间
  - **接单成功通知**(推给用户):字段如 订单编号/师傅姓名/联系电话
  - **订单完成通知**(推给用户,业务语义为维修完成待确认):字段 `character_string5` 订单编号/`thing6` 服务内容/`thing16` 温馨提示——没有它,用户不知道要来确认,全靠 72h 自动确认兜底,感知是"平台没反应"
  - **订单异常提醒**(推给师傅,业务语义为完工被驳回):字段 `character_string6` 订单编号/`thing10` 异常内容/`thing5` 备注——没有它,用户驳回后师傅不刷新页面完全不知情
- 模板 ID 填两处:`miniprogram/utils/config.js`(TPL_ 四项)和 数据库 `config/app` 文档的 `tplNewOrder`/`tplOrderTaken`/`tplOrderFinish`/`tplOrderRejected`
- 若模板字段类型与代码不一致,对应改 `publishOrder`/`grabOrder`/`finishOrder`/`confirmOrder` 里 `data` 的字段名(有注释标记)

### 8. 真机测试(建议两部手机)
1. 手机 A(当用户):发布一条测试维修需求
2. 手机 B(当师傅):申请入驻 → 管理员在管理后台通过审核 + 开通会员 → 接单大厅抢单
3. 走完整流程:抢单 → 电话互通 → 师傅点"维修已完成" → 用户"确认完成" → 评价
4. **并发测试**:两个师傅账号同时抢同一单,应只有一人成功,另一人提示"手慢了"
5. **买空调频道**:手机 B(师傅)发布一件二手空调(全字段)→ 手机 A 在"买空调"tab 浏览筛选 → 详情点"电话联系卖家"取号 → 师傅改价/下架/重新上架/标已售/删除全操作 → 管理后台强制下架一件,师傅侧能看到下架原因

- [ ] **用户隐私保护指引已配置**:mp.weixin.qq.com → 设置 → 服务内容声明 → 用户隐私保护指引,声明收集:位置信息(选择上门地址)、手机号(订单联系)、照片(故障/资质图片)、**身份证信息**(师傅入驻实名审核,身份证正反面照片)。营业执照属企业公开信息,可在"其他信息"一并说明。未配置会导致 `chooseLocation` 等接口被拒

## 关键设计说明(改代码前先读)

- **抢单并发**:`grabOrder` 用云数据库「条件原子更新」——`where(status=='published').update(status='accepted')`,同一单两人同时抢只会有一个 update 成功,无需加锁。
- **隐私**:用户手机号只在师傅**抢单成功后**可见;订单池和围观视角一律脱敏(见 `getOrders` 的 `sanitize`)。师傅资质照片仅管理员可见。
- **会员制而非抽佣**:师傅付会员费获得接单资格,平台不碰维修费 → 没有二清合规问题,师傅也没有飞单动机。**不要**给平台加"代收维修费"功能,那需要支付牌照或微信支付服务商分账资质。
- **内容安全**:所有用户输入文本(需求描述/评价/投诉/入驻资料)过 `security.msgSecCheck`;接口本身故障时放行,命中违规才拦截。
- **订单状态机**:`published → accepted → pending_confirm → completed`,任一前置态可 `cancelled`;用户可将 `pending_confirm` **驳回**退回 `accepted`(防师傅未完工就点完成刷单,驳回次数后台可见);48h 无人接单自动关闭、师傅完成后 72h 用户未确认自动完成(`cronTimeout` 每小时跑)。
- **买空调频道(信息撮合)**:商品状态机 `on_sale → off_shelf/sold/removed`;卖家电话**不落商品文档**,买家点"电话联系卖家"时经 `getListings.contact` 实时取号(服务端复查在售+卖家资格,按人日限频 30 次原子计数);商品文案里贴手机号/微信号/网址会被拦截。上架仅限审核通过的师傅,在售上限 20 件(发布与重新上架两处同口径)。
- **会员时长口径**:按 1 个月 = 30 天顺延(买 12 个月 = 360 天)。线下收款时请向师傅说明,避免"包年"预期差异引发续费纠纷。
- **云存储权限**:必须设为「仅创建者可读写」(部署第 3 步)。照片展示已全部改经云函数换临时链接,不依赖开放读权限;这样任何人拿到 fileID 也读不到师傅身份证照片。**不要**改回「所有用户可读」——那会让资质照片凭 fileID 全网可读。
- **订阅消息的平台限制**:微信「一次性模板」每授权一次只能推送一条。师傅点一次"开启新单提醒"只收到一条推送,之后要再点。这是微信的规则,不是 bug;单量起来后可考虑申请长期模板(门槛较高)或引导师傅常开接单大厅。
